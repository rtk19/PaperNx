## Additional confirmed user feedback

The user confirmed restart reading-position restoration and touchscreen forward/back navigation work. These are regression constraints, not newly discovered defects. Requested improvements: faster turns, persistent global theme across books, every setting from the library, touch-only operation, top-right plus actions, professional categories/settings, intentional fallback covers and responsive settings.

The user subsequently reported that the prior scroll candidate did not expose the expected navigation or vertical swipe behavior on their Switch. Desktop simulation did not resolve that report. New acceptance must record the installed NRO SHA256, EPUB filename, selected navigation mode, actual finger tracking, chapter crossing, restart position and a screenshot of the settings route.

## Source ownership and evidence

Native application composition remains in `src/main.cpp`; small reusable UI and render modules may be extracted as work lands. `src/core.cpp` owns progress and preference serialization; legacy appearance must not silently become intentional per-book overrides. `src/cover_repository.cpp` owns only cache files, never user EPUB/PDF or progress records. `tests/core_tests.cpp`, `tests/app_tests.cpp`, `tests/mupdf_render_tests.c` and `tests/cover_repository_tests.cpp` supply component regressions.

See [V03_REQUIREMENT_COVERAGE.md](V03_REQUIREMENT_COVERAGE.md), [TEST_RESULTS.md](TEST_RESULTS.md) and [PERFORMANCE_RESULTS.md](PERFORMANCE_RESULTS.md) for final source/test coverage. Do not treat older reports as new-candidate verification. The physical protocol is [DEVICE_TEST_PLAN.md](DEVICE_TEST_PLAN.md).

## New physical acceptance protocol

Install the new candidate over application files only, retaining `books/` and `data/`; record NRO SHA256. Detach controllers, start with a large library and film the first screen, plus menu, settings and warm restart. Repeat the six supplied scenarios with the same books when available. Capture cold/warm cover load times, tap-to-first-feedback, settings-open latency, page-turn and scrolling frame gaps, theme/font changes, fit-width pan, suspend/resume and final restart position. Mark each finding PASS/FAIL/UNVERIFIED independently. A stable release remains gated on that evidence.
